# Go Kyrgyzstan — бэкенд

Django-бэкенд с админкой на django-jazzmin для сайта Go Kyrgyzstan.
Туры, направления, фото маршрутов, отзывы, команда и FAQ редактируются в админке
на шести языках (en / ru / kg / fr / de / es).

Контент сайта (8 туров, 7 направлений, 10 фотографий, все переводы) уже
лежит в репозитории и загружается миграциями — после `migrate` админка сразу
заполнена, ничего доливать не нужно.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python manage.py migrate          # создаёт БД и загружает демо-данные
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver
```

Админка — <http://127.0.0.1:8000/admin/>. Корень сайта редиректит туда же.

В текущей локальной БД уже есть пользователь `admin` с паролем `admin` —
смените его перед тем, как выкладывать проект куда-либо.

## Структура

| Путь | Что внутри |
| --- | --- |
| `config/` | настройки, URL-ы, конфигурация Jazzmin |
| `catalog/models.py` | модели контента |
| `catalog/admin.py` | админка: превью, вкладки, инлайны |
| `catalog/api.py` | JSON для фронтенда |
| `catalog/seeding.py` | загрузка демо-данных |
| `catalog/seed/` | `seed.json` + исходные фотографии |
| `catalog/static/catalog/` | CSS и JS админки (галерея-лайтбокс) |
| `media/` | загруженные фото (создаётся при первой миграции) |

## Работа с фото

Все изображения лежат в одной **Фотобиблиотеке**: alt-текст пишется один раз на
фото, а туры и направления на него ссылаются. Это значит, что одну и ту же
фотографию можно использовать в нескольких местах, не дублируя файл.

В карточке тура фото маршрута собраны в блоке **«Фото маршрута»**. Любая
миниатюра в админке открывается в полноэкранной галерее: стрелки ← → или кнопки
по бокам листают все фото блока, Esc закрывает.

## Переводы

Для каждого текста заведены шесть полей — `name_ru`, `name_en`, `name_kg`,
`name_fr`, `name_de`, `name_es` и так далее. Они собраны во вкладки: «Название»,
«Краткое описание», «Описание» и другие, в каждой — все шесть языков рядом.
Немецкий и испанский необязательны: пока поле пустое, сайт показывает английский.

Поля, где перечисляются пункты («Входит в стоимость», «Изюминки», текст
страницы) — это обычные textarea: **один пункт или абзац на строку**.

## Базовые данные

Источник правды — `catalog/seed/seed.json`. Его загружают две миграции:
`0002_seed_demo_content` заливает каталог на чистой базе, а
`0003_add_grand_tour_and_horseback` дополняет уже заполненную — так в проект
приезжает новый контент, не затирая правки в админке.

```bash
python manage.py seed_demo --sync     # дозалить то, чего нет в базе
python manage.py seed_demo            # только если каталог пуст
python manage.py seed_demo --reset    # удалить контент и загрузить заново
python manage.py seed_demo --translations  # заполнить только пустые поля переводов
```

`--sync` — то, что нужно после правок в `seed.json`: он создаёт недостающие
туры, направления и фото и не трогает всё остальное. `--reset` удаляет контент
целиком; заявки и пользователи не затрагиваются ни в одном режиме.

Новый тур в `seed.json` должен повторять структуру существующих: шесть языков в
каждом текстовом поле, `days` по порядку с 1, одинаковая длина списка `notes` во
всех локалях и ссылки на существующие ключи фотографий.

## API

Сайт (`../go_travel`) берёт отсюда весь контент — тексты, фотографии и
контакты. Всё отдаётся в одной локали за раз: `?locale=ru` (по умолчанию `en`).

| Метод | Адрес | Что отдаёт |
| --- | --- | --- |
| GET | `/api/tours/` | список туров (`?featured=1` — только для главной) |
| GET | `/api/tours/<slug>/` | тур целиком: маршрут, галерея, заезды, «полезно знать» |
| GET | `/api/destinations/` | список направлений |
| GET | `/api/destinations/<slug>/` | направление с галереей |
| GET | `/api/photos/` | вся фотобиблиотека по ключам — для шапок страниц |
| GET | `/api/site/` | контакты, цифры, команда, отзывы, FAQ, галерея, фото главной |
| POST | `/api/inquiries/` | сохранить заявку с сайта |

CORS открыт для `http://localhost:3000` — меняется переменной
`DJANGO_CORS_ORIGINS`.

`/api/inquiries/` только сохраняет заявку, чтобы её было видно в разделе
«Заявки». Источник правды по лидам остаётся amoCRM: сайт отправляет их своим
роутом `/api/inquiry` и уже оттуда дублирует сюда.

## Связка с сайтом

Сайт читает этот бэкенд по адресу из `API_BASE_URL` (по умолчанию
`http://127.0.0.1:8000`) и кеширует ответы на 60 секунд. Правка в админке
появляется на сайте в течение минуты — пересобирать ничего не нужно.

**Во время `npm run build` бэкенд должен быть запущен**: страницы туров и
направлений пререндерятся из этого API. Если он недоступен, сборка падает с
`ECONNREFUSED`.

Фотографии отдаются из `media/`, поэтому в проде их должен раздавать nginx —
сайт грузит их напрямую с этого хоста.

## Переменные окружения

Все со значениями по умолчанию для разработки, `.env` не нужен.

| Переменная | По умолчанию |
| --- | --- |
| `DJANGO_SECRET_KEY` | небезопасный ключ для разработки |
| `DJANGO_DEBUG` | `1` |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1` |
| `DJANGO_CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | пусто |
| `DJANGO_LANGUAGE_CODE` | `ru` |

Перед публикацией задайте `DJANGO_SECRET_KEY`, поставьте `DJANGO_DEBUG=0`,
перечислите домены в `DJANGO_ALLOWED_HOSTS` и отдавайте `media/` и `staticfiles/`
через nginx — в DEBUG их раздаёт сам Django.
